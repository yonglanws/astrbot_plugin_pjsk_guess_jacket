# 猜曲绘排行榜与猜卡面排行榜对齐设计

## 背景

当前两个插件使用相同结构的玩家统计字段，但排行榜图片实现不同：猜卡面使用 850px 横向表格布局，显示排名、玩家、总分、正确率和总次数，并支持前三名奖牌、黑名单统一显示、自定义名称、玩家原名称与 ID；猜曲绘使用白色圆角卡片布局，字段位置和文案均不一致。

## 目标

- 让猜曲绘排行榜的图片布局、尺寸、颜色、字体字号、字段顺序、排名奖牌、截断规则、ID 行和页脚与当前猜卡面排行榜一致。
- 猜曲绘标题使用对应的“PJSK猜曲绘排行榜”文案，其余视觉和展示规则保持一致。
- 同步排行榜命令的等价别名、无数据提示和生成失败提示，同时保留现有猜曲绘别名以避免兼容性回退。
- 排行榜继续读取 `jacket_user_stats`，不与猜卡面的 `user_stats` 合并或共享分数。
- 黑名单用户在排行榜中的主名称显示为 `[此用户已被BOT拉黑]`，自定义名称优先级与猜卡面一致。

## 实现方案

1. 将曲绘 `ImageGenerator` 的排行榜字体预加载改为猜卡面使用的标题、表头、正文、ID 和奖牌字号。
2. 将 `create_ranking_image` 改为猜卡面的横向表格绘制流程：850px 宽度、渐变背景、标题阴影、五列字段、前三名奖牌、分隔线和时间页脚。
3. 使用 `Pilmoji` 绘制奖牌 emoji，并将其加入曲绘插件依赖，确保排行榜在独立安装时具备与猜卡面相同的渲染能力。
4. 在曲绘插件中补充与猜卡面一致的 `_get_display_name` 规则；渲染器通过显示名称回调使用该规则，而不是复制黑名单配置状态。
5. 排行榜命令继续调用曲绘数据库的 `get_ranking`，将显示名称回调传入渲染器；查询数量保留当前安全限制，并兼容猜卡面对应的别名和已有曲绘别名。

## 非目标

- 不迁移或合并两个插件的 SQLite 数据库。
- 不修改积分计算、答题次数、每日限制或用户自定义名称存储逻辑。
- 不修改猜卡面插件本身。
- 不复用猜卡面插件的代码文件路径；曲绘插件保留自己的实现，避免两个插件互相导入。

## 测试设计

- 用无 AstrBot 运行时的标准库测试桩导入曲绘插件，验证渲染器使用 850px 宽度、动态高度公式和五列字段所需的布局参数。
- 验证显示名称回调：普通用户优先显示自定义名称，黑名单用户显示 `[此用户已被BOT拉黑]`。
- 验证排行榜命令把曲绘数据库查询结果交给新的渲染器，并保留曲绘数据库数据源。
- 使用本地字体和 `Pilmoji` 测试替身生成示例图片，确认输出路径存在且图片尺寸/模式正确；不访问远程曲绘服务。
- 保留并重新运行既有曲绘加载重试测试。

## 验收标准

- `猜曲绘排行榜` 生成的图片与猜卡面排行榜具有相同的横向表格结构和字段顺序。
- 曲绘排行榜不再使用原来的白色圆角卡片布局。
- 黑名单、自定义名称、前三名奖牌、ID、正确率、总次数、总分和页脚行为与猜卡面一致。
- 原有猜曲绘排行榜别名仍可用，新增的等价别名可用。
- 曲绘分数数据仍只来自 `jacket_user_stats`。
- 新增测试、既有测试、Python 编译检查和 `git diff --check` 均通过。
